DSH 插件开发 · 课程总览

从一棵树，到一个能装的插件

七章。每一章都让你能在命令行或界面上看见一个结果。

目标已锚定到 dialog-box 项目 环境：本机桌面版 0.2.1-rc.2

整条线的形状。第一章你先看见「树」，知道一棵跑起来的 DSH 是叠出来的。第二、三章钻进去看「一行」背后到底是什么——一个 53 行的模块，和它为什么能在卸载时自动收拾干净。第四章退回来讲清楚「层」的机制，也就是你以后装自己东西的位置。第五章分叉：写进程内的能力，还是写浏览器里的界面。第六章讲拦截，第七章把东西打包装上。

七章走完，你手上会有一个能装进这台机器、界面上看得见、并且是你自己写的插件。dialog-box 的 V1 就从这儿起步。

三可复用的实验工具

这台机器没有把 dsh 装进 PATH。桌面版的 CLI 在 app.asar 里面，需要特殊开关才能调用。我写了个垫片：

pwsh -NoProfile -File .\scratch\dsh.ps1 --version
pwsh -NoProfile -File .\scratch\dsh.ps1 --profile web --dump-config

参数原样透传。--dump-config 不写任何文件，可以放心反复跑。

为什么实验都用 web profile

desktop 是你每天用的树，15 个 bundle，里面还有插件自动维护的区块，手改容易互相干扰。web 是干净的官方模板，只有 2 个 bundle，坏了删掉重来就行。
