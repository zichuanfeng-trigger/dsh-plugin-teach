# 任务确立：从「学架构」改为「能开工」

小枫的原始请求是"从最开始的架构开始学 DSH 插件开发"。他补充指向了隔壁的私研究仓库 `dialog-box`，那份仓库已有 6 篇成文调研、4 份原始调研、9 份 asar 证据，但代码一行未写。

这条信息改变了教学重心：他不需要"了解 DSH"，他需要"让那个真实项目能开工"。所以 `MISSION.md` 的成功标准被写成可交付物（最小插件装进桌面版、读懂第三方插件源码、V1 切片跑起来），而不是知识点清单。

## Implications

- 每课必须收束到"你能不能动手"而不是"你知不知道"
- 架构课的深度以"够用来判断自己的代码落在哪一层"为界，不追求 Cordis 内部实现的完整
- 课程用 `web` profile 做实验（干净、2 个 bundle），不碰日常使用的 `desktop` profile
- 不 clone 源码、不跑 pnpm install：所有验证走 `--dump-config` 与本地 bundle

## Evidence

用户原话：「好问题，我的想法是1和2。你可以看看隔壁仓库 dialog-box」。选项 1 与 2 分别是"自己能做出一个装进 DSH 的插件"和"能读懂别人写的插件源码并改造"。
